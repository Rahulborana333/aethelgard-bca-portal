📁 Blueprint Pattern

Code is split into 4 modules: auth, views, api, admin. Each module handles its own routes independently — easy to maintain and debug.

🔄 MVC Architecture

Model = database tables (models.py), View = HTML templates (Jinja2), Controller = route functions (routes/). Industry-standard design pattern.

📡 Event-Driven (SocketIO)

Study Room uses WebSocket events. When a student sends a message, the server broadcasts it to ALL connected users instantly — no page refresh needed.

⚡ Challenges & Solutions

Problems We Solved

🔌 Port Conflict (OSError: Address in use)

Problem: Moving the folder left old Python processes running on port 5001.
Fix: Used lsof -i :5001 to detect zombie processes and killed them. Added a one-liner startup script to auto-clear port before launch.

🔐 Secure Authentication Setup

Problem: Standard session auth is insecure; plain cookies can be tampered.
Fix: Implemented JWT (JSON Web Token) stored in HttpOnly cookies. Every route checks the token before serving any data.

🗄️ Database Column Migration

Problem: Needed to add is_active column to existing database without wiping data.
Fix: Used ALTER TABLE user ADD COLUMN is_active inside a try/except block — safe and automatic.

📡 Real-Time Message Broadcast

Problem: HTTP is one-way — browser requests, server responds. Can't push live messages.
Fix: Integrated Flask-SocketIO + Eventlet. WebSocket keeps a persistent connection so server can push messages to ALL connected clients instantly.

🧑‍💼 Role-Based Access Control

Problem: Students should not access admin routes; admins need separate permissions.
Fix: Added role field (student/admin) to User model. Every admin route checks JWT identity and role before allowing access.

⏰ Background Scheduler Conflict

Problem: APScheduler started twice in debug mode (Flask reloader runs app twice).
Fix: Added if not scheduler.running: scheduler.start() guard to prevent duplicate scheduler instances.
